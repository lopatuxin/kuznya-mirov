# Очистка сборок Rust на Windows

В корневой `.cargo/config.toml` отключён incremental-кэш. В режимах dev и test
сохраняются только отладочные таблицы строк: сообщения об ошибках по-прежнему
могут показывать файл и строку, но значения локальных переменных в отладчике
недоступны. Проверки переполнений и debug assertions не отключаются.

`install-rust-cache-cleanup.ps1` устанавливает задание Windows
`KuznyaMirov-RustCacheCleanup` для текущего пользователя: при входе и каждый час.
Работает без Claude и Codex, когда пользователь вошёл в Windows.

`clean-rust-cache.ps1 -Apply` обслуживает `target` у `engine/`, `importer/` и библиотек
в `engine/vendor/` в основной папке проекта и в `.claude/worktrees/*`.
Старые рабочие копии с `luars/` и `cosmic-text/` в корне тоже обслуживаются.
Нестандартные `CARGO_TARGET_DIR` за пределами этих папок не обслуживаются;
временные сборки нужно удалять после завершения их задачи.

Общий порог — 8 ГиБ. При превышении очищаются самые старые профили сборки,
пока размер не станет ниже порога. Профили без изменений 7 дней очищаются
независимо от размера. За последние 30 минут изменённые файлы не очищаются.
Это порог отложенной очистки, а не жёсткая дисковая квота: текущая сборка
может временно превысить его. После очистки Cargo соберёт нужные файлы заново.

Если работает Cargo, rustc, rustdoc, wasm-pack или rust-lld, запуск пропускается.
На время удаления удерживается эксклюзивная блокировка Cargo `.cargo-lock`;
все файлы блокировок остаются на месте. Символические ссылки и junction
в очищаемых путях запрещены. Исходники, `engine/pkg` и игровые материалы
очистка не затрагивает.

Без `-Apply` скрипт показывает план и ничего не удаляет. Последний результат
задания записывается в `.cargo/cache-cleanup-status.json`, без накопления логов.
Удалить задание: `Unregister-ScheduledTask -TaskName KuznyaMirov-RustCacheCleanup`.
Откатить облегчённые сборки: удалить добавленную `.cargo/config.toml`.
